# Scientific and classroom qualification — V6.2.1

## What this update establishes

The application remains V6.2.1. Scientific accuracy across every possible topic cannot be proven by retrieval, an LLM or a passing software test. Keep three separate outcomes: software contract passed, source passage traceable, and independent scientific review completed. None implies the others.

Implemented:

- Europe PMC open-access article-body XML retrieval, bounded to six articles per generation request and 2 MB per download. JATS paragraphs retain body order; figures, tables and reference lists are excluded from text extraction. Abstract-only responses never become full text. Full text and quoted passage provenance are preserved in projects. Open access does not establish peer review or unrestricted figure reuse; article-specific terms remain visible.
- CDC, WHO, OpenStax, NCBI and Europe PMC source library: public HTTPS publisher allowlist; open HTML extraction when browser access permits; explicitly labelled lecturer-passage import otherwise. No arbitrary website crawler or PDF extraction. Exact passages, locator, edition/version, acquisition method, reuse terms and retrieval date survive offline reopening and portable backup. Current source-library selection is stored locally for subsequent research generation; it is not a cloud service.
- Default research excerpt generation excludes indexed preprints and records with known retraction, concern, correction or notice metadata. Full-text access and authoritative teaching documents rank above abstract-only records after topical filtering. This is a transparent retrieval preference, not an automated study-quality assessment.
- Incoming Crossref updates and Europe PMC correction/retraction links are checked independently of title/identifier matching. The check date, providers, completeness and notice URLs are visible and saved with citations. Unknown, partial, cached and stale checks cannot be described as a clean scientific bill of health. Partial connectivity cannot clear a cached adverse notice. Known adverse notices and identifier/title mismatches block reviewed export; draft export remains available. Correction quarantine is deliberately conservative: inspect and replace affected source relationships before reviewed export.
- The seven-day publication-check refresh and thirty-day guideline-confirmation interval are application review policies, not scientific expiry dates. Guidance requires publisher version/date, population/jurisdiction and explicit lecturer confirmation of current publisher status. Claims classified as guidelines cannot rely on an abstract alone. The application does not automatically establish that a publisher page is the latest applicable clinical recommendation.
- Optional Ollama embedding review scans all teaching statements in batches with truncation disabled. It returns related-statement candidates, model name, cosine score and threshold. Altered numbers/negation are surfaced separately. Up to 400 statements; excessive decks fail explicitly. The default 0.90 threshold is uncalibrated. No model or model failure means no semantic verdict, never a pass. No automatic deletions. The screen shows the first 100 candidates; the downloaded report includes all candidates.
- Source-aware claim editor: choose a saved source, supply an exact supporting passage, select actual access and explicitly review it. Quotes from saved documents must occur in that document; textual occurrence does not prove entailment. Claim evidence and publication notices are carried in PPTX speaker notes without appending slides.
- Research requests retry transient failures within the existing three-round / 75-second budget. Failed connectivity is distinguished from an empty or insufficient source result, and the active deck is preserved.
- Evidence candidate assembly uses bounded incremental duplicate screening rather than repeatedly auditing every historical pair. The final exact-count and duplicate gates still run before replacing work.

## Reproducible software and live benchmarks

`npm run test:scientific` runs deterministic contracts, including real provider notice-label forms, notice direction, identifier mismatch, future/stale timestamps, malformed XML, hostile publisher URLs, guideline requirements, vector validation, adverse-source export blocking, provider failure and source preservation. These tests use fixtures; they are not a scientific accuracy score.

`benchmarks/microbiology-topics.json` defines 200 distinct topics across 20 areas, including bacteria, archaea, viruses, fungi, parasites, genetics, genomics, immunology, AMR, diagnostics, infection prevention, epidemiology, environmental/food/industrial microbiology, microbiomes, One Health, methods and guidance appraisal. It is a coverage manifest, not a gold standard. Every case starts `needs-independent-review`.

`npm run benchmark:live` retrieves real evidence, forces research generation instead of rewarding bundled templates, checks exact count, records source access and claim traceability, queries publication notices, archives the generated deck locally and measures elapsed time. It never silently substitutes source fixtures or marks a deck classroom-ready. Default: first three cases. Environment controls `JUW_BENCH_START`, `JUW_BENCH_LIMIT`, `JUW_BENCH_STRIDE`, `JUW_BENCH_OUTPUT`; a balanced first-case-per-domain sample uses stride 10 and limit 20. The GitHub manual workflow supports the full 200-case run. Results record commit, machine, partial failures and missing scientific/semantic verdicts. A failed retrieval is a failure, not padding. Exit is nonzero if any case is incomplete.

For every case and every supported count, qualification requires:

| Measure               | Release criterion                                                                                                                                                                                          |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exact count           | 100% of successful requests deliver exactly 1–50 as requested; report incomplete requests separately                                                                                                       |
| Coverage              | 200 topics, all 50 requested counts, clinical and nonclinical scope; no hidden topic exclusions                                                                                                            |
| Source traceability   | Every factual statement linked to an exact archived source passage/locator or explicitly labelled textbook/consensus basis                                                                                 |
| Scientific accuracy   | Two independent qualified microbiology educators; all material errors corrected; disagreements adjudicated; never infer this from quote matching                                                           |
| Conceptual repetition | Independently labelled paraphrase/contradiction corpus; sensitivity ≥95%, precision ≥95%, confidence intervals reported by domain; no model threshold selected using the holdout                           |
| Clinical guidance     | Current applicable primary guidance and correction/retraction metadata checked at export; unresolved clinical claims block reviewed release                                                                |
| Timing                | P95 under five minutes from request to reviewed professional deck on a specified representative Windows laptop, including retrieval/model startup and review; retrieval-only timing is reported separately |

Independent reviewers must record case ID, deck SHA-256, source snapshot SHA-256, domain expertise, review date, all factual errors (including titles, captions and notes), contextual omissions, redundant concepts and adjudication. Do not commit third-party copyrighted full texts to the repository. Review pseudonymized results separately from private reviewer identity. Holdout sets must be independently authored and kept out of model prompts, heuristic development and threshold selection. No independent reviewers or calibrated embedding model are bundled in this release.

`npm run benchmark:semantic` evaluates an explicitly supplied installed local embedding model (`JUW_EMBEDDING_MODEL`, optional `JUW_EMBEDDING_URL`) against 27 development pairs across seven domains. It writes an exploratory report; missing models exit nonzero with `not-tested`. These labels are not an independent gold standard, and the resulting precision/recall must never be advertised as calibrated accuracy. Expand, independently label and hold out the corpus before qualifying thresholds.

## Actual PowerPoint qualification

The manual `Actual PowerPoint qualification` workflow requires a disposable, logged-on Windows lab runner labelled `juw-powerpoint`, with licensed desktop Microsoft PowerPoint. It must never run untrusted pull-request code. GitHub-hosted Windows has no licensed PowerPoint; hosted CI success is not renderer qualification.

1. `JUW_QUALIFY_PPTX=1 npm run qa:pages` creates 50 theme/layout preview rasters at 1280×720 and the matching editable PPTX.
2. `scripts/qualify-powerpoint.ps1` opens the export in actual PowerPoint, exports PNGs, inventories editable text, verifies notes, edits a title, saves a copy and verifies the edit after reopening. Missing PowerPoint writes `not-tested` and exits nonzero. It does not substitute another renderer.
3. `scripts/compare-powerpoint.py` compares the actual render with preview, saves every diff and applies explicit initial release limits: normalized mean channel error ≤0.005 and ≤2% pixels differing by >32. The intentional draft label is the only masked region. These limits require visual review and can fail; they are not a promise of pixel identity. Install Pillow 11.3.0 in the qualification environment.
4. A reviewer inspects all diffs, multilingual/scientific glyphs, font fallback, figure captions/attribution and paragraph editing in PowerPoint. Existing text remains editable as native lines; whole-paragraph reflow is not qualified.

Physical classroom qualification remains pending until witnessed evidence is attached.

Use `benchmarks/classroom-qualification.json` as the release checklist. Record OS/build, CPU/RAM/GPU, display topology/DPI, PowerPoint/WebView2 versions, app commit, installed local models, cold/warm timing and evidence paths. Required cases include cold airplane-mode startup after setup; cached-topic generation with model ready; uncached-topic failure preserving work; source-library and project reopen; offline export; projector hotplug and removal; mixed 100/150/200% DPI; monitor rearrangement; sleep/resume; locked session; keyboard/screen-reader operation; low disk; power interruption; long lecture and large figures. ## Reproducible development calibration and external review — 2026-10-20

The semantic corpus now has 27 pairs across seven domains. Six source-backed hard cases distinguish condition changes from contradictions, bacterial endospores from fungal reproductive spores, cellular ribosome contexts, RNA detection from infectiousness, and equivalent negative-test interpretations. Proposed labels include intentionally false statements as counterexamples: they are benchmark material, not teaching content. The new source-backed labels were reviewed by AI against OpenStax and CDC on 2026-10-20; they are **not independent human labels**. Neither an authoritative citation nor a cosine score establishes scientific correctness.

`benchmark:semantic` retains every raw cosine, including below-threshold scores. It separates whole domains before embedding and rejects duplicate IDs and identical statements leaking between partitions. Threshold selection uses calibration F1, then precision, then the higher threshold as deterministic tie-breakers. The evaluation partition cannot select the threshold. This is a developer evaluation partition, **not a blind external holdout**: all committed labels are public and available to developers. Reports include the corpus SHA-256, installed model digest checked before/after the run, model identity/dimensions, runtime, commit/dirty status, timings, confusion counts, precision/recall/F1, contradiction false-positive rate and descriptive Wilson intervals. Shared anchor pairs violate independence assumptions, so those intervals are not release confidence bounds. Missing models, changed models, malformed vectors and partial runs fail explicitly. No production threshold is changed automatically.

Embedding screening in the app now uses `related-statements` and `changed-wording-review` labels. Its number/negation flag cannot establish contradiction; related statements can be distinct necessary concepts or conflicting assertions. Human inspection of scientific scope and source context remains necessary even when the screen finds zero pairs.

### A concrete review handoff

`npm run review:scientific -- pack saved-deck.json output-directory` generates a content-hashed pack and two separate blank reviewer forms. Each pack includes every nonempty title, subtitle, note and teaching bullet, matched claim passages, references and attached figure metadata. Saved source documents are fingerprinted. It contains potentially private notes and quoted evidence: keep it private and share deliberately. Do not publish third-party full texts. Reviewers receive separate forms and do not see each other's decisions; the coordinator must arrange this separation. The software does not authenticate reviewer identities or enforce external blinding.

Reviewers fill credentials, independence/conflict declarations, completion date, and one decision per item (`supported`, `revise`, `remove`, `not-factual`), source URLs, rationale and cross-item `redundantWith` IDs. `supported` requires an HTTPS source; the coordinator must verify that the source actually supports the specific claim. `not-factual` is for genuinely nonfactual labels, never an escape from sourcing scientific assertions.

`npm run review:scientific -- assess output-directory/pack.json reviewer-A.json reviewer-B.json` rejects stale hashes, missing/duplicate reviewers, missing decisions, empty rationales, invalid dates and missing scientific-source links. Any revise/remove decision, identified redundancy or reviewer disagreement requires correction/adjudication. Correct the deck, generate a new pack and obtain new reviews. The tool reports only attestation completeness: `independentlyVerified` and `scientificCertification` remain false. A coordinator must independently verify qualifications, identities, conflicts, subject coverage and adjudication. Review results do not silently modify the app's lecturer review or classroom-readiness state.

## Measured local semantic evaluation and source-context hardening — 2026-10-20

A real CPU run is now recorded in [semantic-minilm-2026-10-20.json](qualification/semantic-minilm-2026-10-20.json). It used Transformers.js 3.8.1, ONNX Runtime CPU with two intra-op threads, q8 `Xenova/all-MiniLM-L6-v2` at publisher revision `751bff37182d3f1213fa05d7196b954e230abad9`, mean pooling and normalized embeddings. All five model/tokenizer files and the runtime entry module are hashed; inference disallows remote models and checks token capacity without truncation. The approximately 23 MB weights were downloaded for this evaluation, not added to the app or repository. No paid inference API was used.

At the app's fixed 0.90 screening threshold, the 27 development pairs produced TP=2, FP=2, FN=6, TN=17: precision 0.50 and recall 0.25. The calibration partition selected 0.77 by its predeclared rule; its six-pair development evaluation partition produced TP=2, FP=1, FN=0, TN=3. These are small public developer/AI-reviewed sets, not an external blind holdout. **Disposition: model/threshold not qualified for reliable scientific repetition detection.** The threshold is not applied automatically. This ONNX result does not qualify another model, Ollama conversion, device or scientific domain. Embedding similarity cannot establish factual truth. Runtime timings are Linux-host measurements, not Windows/classroom performance claims.

`npm run benchmark:semantic:local` is an optional developer benchmark. Install the pinned Transformers.js runtime separately, provide `JUW_TRANSFORMERS_MODULE` (its `dist/transformers.node.mjs`), `JUW_EMBEDDING_DIRECTORY` (local config, tokenizer files and `onnx/model_quantized.onnx`) and `JUW_EMBEDDING_PROVENANCE` (publisher/revision). The script neither installs dependencies nor downloads models and writes `not-tested`/`incomplete` for missing inputs or failures. The existing Ollama benchmark remains separate. Publisher instructions: https://huggingface.co/Xenova/all-MiniLM-L6-v2 and https://huggingface.co/docs/transformers.js/v3.8.1/en/index .

Source generation now preserves paragraph boundaries and adjacent sentences. It does not combine sentences across discarded text, paragraph changes or section headings. A topic-relevant result retains an adjacent qualification even when that qualification omits the topic keyword. Source paragraphs over 6,000 characters are excluded rather than silently truncated, and selected paragraph context is copied verbatim into speaker notes. Plain abstract markup removal preserves literal comparison signs, inline scientific terms and Unicode numeric entities. Saved-source quotation checks still apply. Single-slide source selection prefers explanatory wording over first-person study-result narration; this is a pedagogical heuristic, not proof of adequate topic coverage. A new content-derived research cache key avoids reuse of older flattened passage candidates. The visible app version remains V6.2.1.

The Review panel now also accepts the original pack and two returned JSON forms offline. It checks pack/item hashes against the current slide text, notes, figures and source snapshots. It rejects stale content and malformed forms; counts incomplete decisions, corrections, redundancy and disagreements; and exports the assessment through the native save dialog on Windows. Reviewer identity/qualifications/independence remain self-attested. Even complete forms do not change the deck's lecturer evidence state or unlock reviewed export. The CLI and app share the same assessment logic.

A live source-context smoke cohort is archived in [source-context-live-2026-10-20.json](qualification/source-context-live-2026-10-20.json): bacterial endospores (10), bacterial conjugation (50), antimicrobial susceptibility testing (10), and microbial fermentation scale-up (50). All four counts completed, with 254/254 teaching claims carrying recorded passages, zero lexical duplicate pairs and 56/56 full-text evidence quotations contained in saved source text after whitespace normalization. Measured retrieval and metadata-check times were 26.289, 69.691, 27.493 and 100.220 seconds. Some publication checks remained partial/unknown. These 120 slides are software/source-traceability checks, not an independently reviewed broad-domain gold corpus; abstracts still comprise most claims. Every deck remains `classroomReady: false` and `needs-independent-review`. The run records its source fingerprint and dirty-worktree state, not a misleading final-build attestation. A reporting correction preserves the original semantic-status label while clarifying that the separate CPU model test did not screen these decks.

The app's Ollama semantic screen now requires the installed model digest before and after screening, a stable nonempty model name, valid complete vectors, and at least one teaching statement. A changed/missing model identity fails explicitly. Its downloaded report includes the digest and an explicit `independentlyCalibrated: false`; it never infers qualification from the mere existence of a model.

## Guided review software qualification — 2026-10-20

The reviewer workspace makes the existing human handoff usable without hand-editing JSON. Software checks cover original pack/item hashes, incomplete draft resumption, foreign/tampered forms, pending decisions, declarations, safe source links, portable completed forms, offline recovery and explicit deletion of local checkpoints. Browser fixtures contain synthetic decisions and credentials: they are not completed independent human reviews. Completion checks attest only to form consistency and required fields; they cannot verify reviewer identity, source interpretation, figure pixels, clinical currency or scientific truth. The coordinator remains responsible for independent reviewers and adjudication.

They qualify these software paths only. ## Enforced export and qualification workflow — 21 October 2026

The V6.2.1 reviewed-export gate now treats missing, partial, unknown, stale or identity-unconfirmed DOI/PMID checks as critical findings. A fresh complete `no-notice-found` check and a matching bibliographic title are required. This is publication-metadata evidence, not endorsement of a study. Offline draft export remains available; a source check never silently becomes current without network evidence.

The claim evidence panel now includes **Headings, notes and figures**. Every nonempty title, subtitle and notes field needs an explicit lecturer decision. Factual fields require a supporting HTTPS source, exact passage, locator and rationale. Administrative/nonfactual text requires an explicit rationale instead. Attached figures require source support, creator and concrete reuse terms; the same panel allows attribution corrections. The lecturer must inspect pixels and scientific context. This software cannot detect a false attestation.

Decisions bind to a SHA-256 digest of the current text, topic/level, figure bytes/source, provenance, bibliography and saved-source metadata. Changes invalidate the decisions; saved-source quotations are independently checked for containment. These records survive JSON and portable project roundtrips and appear in PPTX speaker notes. Reviewed figures require a local image snapshot so a remote URL cannot silently serve changed pixels; the panel can capture permitted raster files explicitly. Re-encoding or replacing a figure invalidates prior decisions and requires review again. Older projects load without deletion but their newly covered fields start unreviewed. This is a stricter lecturer gate, **not independent microbiology certification**. Complete external-review forms still do not authenticate identity or unlock export automatically.

Cancellation now aborts an in-flight local Ollama request instead of waiting for its network timeout. Completed valid batches remain resumable. Aborted generation does not enter the research fallback or replace the saved lecture. This closes the local-model cancellation implementation gap; it does not promise immediate interruption of a remote model's computation after its HTTP connection is closed.
