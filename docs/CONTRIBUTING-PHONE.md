# Contributing from a phone

1. Open https://github.com/Tajoor621/JUW-MicroSlides in the browser. Sign in to your own GitHub account. Never put credentials or API keys in issues or source files.
2. Open a file, choose the pencil/Edit action, and make a focused change. Use **Commit changes → Create a new branch and start a pull request**. For several files, use GitHub's web editor (`github.dev`); it edits files but cannot run the app or tests.
3. Describe the visible problem, what changed, and how to reproduce it. Keep **V6.2.1 / 6.2.1** in all active identity surfaces. Never delete saved-data migration code, evidence fields or saved-project compatibility. Do not restore export review gates.
4. Open the pull request's **Checks** tab. Wait for Pages verification, Windows build/UI and dependency security checks. A green code check does not prove scientific accuracy or real-phone compatibility. Inspect failed job logs rather than merging around failures.
5. After approval/merge, wait for **Verify and deploy Pages**, including its public smoke test. Open the canonical app URL; choose **Check for updates → Load latest build** and check the new commit ID.
6. Follow [QA.md](QA.md) for the phone, keyboard, offline and PowerPoint checks. Export a library backup before updates; keep it in device Files or another location outside the browser.

For a bug report, include build ID, browser/OS, topic, requested count, action, visible error and a redacted screenshot. Never post patient/student data, private lecture notes or unlicensed figures. Files shared publicly in GitHub issues are public.
